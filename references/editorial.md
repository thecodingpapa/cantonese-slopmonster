# 編輯原則：寫畀人講嘅香港廣東話

呢份係 v0.1 嘅人工編寫準則，未經獨立母語編輯評核。例句係本項目由 AI 原創，唔係真實頻道稿、訪談摘錄或者語料庫引文。

## 語體先行

目標係香港口述稿：保留自然嘅「我哋、嘅、喺、冇」等結構，但唔要求每句出現呢啲字。繁體字只係字形；「我們將進行深入探討」就算全句繁體，仍然可以同目標口語有距離。

| 情境 | 可以點處理 | 唔應該做 |
|---|---|---|
| 「我們會展示這個設定。」 | 「我哋會示範呢個設定。」 | 見「會、需要、如果、因為」就一律換字 |
| 「他沒有開啟通知。」 | 「佢冇開通知。」 | 改成「佢唔想收通知」而添咗動機 |
| 「這個方法可能有用。」 | 「呢個方法可能有用。」 | 刪「可能」，變成效果保證 |
| 「我哋用 API 傳資料。」 | 可以保留 API | 硬譯成熟悉程度更低嘅名稱 |
| 「文件寫明『不得轉讓』。」 | 原文照引；有需要再用旁白解釋 | 將法規原句偷偷改成口語 |

「畀／俾」、「咁／噉」等寫法有使用差異；優先跟返作者既有選擇。v1 唔會用其中一種寫法判錯。唔用單一詞庫代表所有香港人嘅聲線。

## 唔好靠口頭禪扮自然

句末語氣詞有態度同語用功能，唔係裝飾。只喺語氣需要嘅地方留。唔擅自加粗口、潮語、「老實講」或者「你都知我一向……」。觀眾未提供就唔假設年齡、地域經驗、購買力或喜好。

講清一件事通常比抽象讚美有用。例如「提供無縫體驗」如果原資料只係講一個按鈕，就描述嗰個已知操作；資料不足就提出問題。唔好為咗具體而作一個例子扮事實。

## 用句子而唔係字表執稿

一個停頓通常處理一個重點。長句可以分開，但保留「如果」、「除非」、「未必」、「只限」之類限制。段落可以有長有短；唔需要每段三點、每段先問後答，亦唔需要刪走所有排比或總結。

技術教學可以精準，講故可以有節奏；唔好將所有片種都改成同一個輕鬆主持人格。正式題材仍然可以用清楚嘅廣東話解釋。引用、術語、字幕文案同主持旁白可以有唔同語體。

## 保留意思嘅人工覆核

將原稿嘅每項主張逐項對住新稿：

- 邊個做咗乜？人名、品牌、數字同單位係咪仍然指同一樣嘢？
- 係已發生、計劃、推測，定只係某人聲稱？有冇將相關改成因果？
- 有冇漏咗否定、例外、風險、限制或來源？
- 引文、網址、時間碼、拍攝提示同程式碼有冇完整保留？

數字完全一樣但交換咗兩個產品嘅數值，字面檢查仍然可能通過。唔可以用工具取代呢一輪覆核。
